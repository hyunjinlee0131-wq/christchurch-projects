# Best Park + Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship "Best Park in Christchurch" as a public ranking site on GitHub Pages: a data score for every real park, a personal ranking you can reweight, per-park share pages, and user voting (People's Choice). This also builds the site template, the Supabase vote/feedback store and the monthly refresh workflow that later projects reuse.

**Architecture:**
- A Python pipeline (`projects/best_park/`) built on `ccc_data` scores parks and writes small JSON/GeoJSON outputs that are committed to the repo.
- An Astro static site (`site/`) copies those outputs at build time and renders the leaderboard, a MapLibre map and per-park pages.
- Votes and 👍/👎 go straight from the browser to Supabase's REST API (no SDK), protected by insert-only row-level security.
- GitHub Actions deploys Pages on push, and a monthly refresh opens a PR.

**Tech Stack:**
- Python: `ccc_data` (plan 1), geopandas, pandas, pytest.
- Node 24: Astro (pin the exact version installed), MapLibre GL JS, vitest, @playwright/test, @axe-core/playwright, satori + @resvg/resvg-js for OG images.
- Hosting and services: Supabase (Postgres REST), GitHub Pages, GitHub Actions.
- Basemap: OpenFreeMap Positron (`https://tiles.openfreemap.org/styles/positron`, no key).

**Spec:** `docs/superpowers/specs/2026-11-01-ccc-spatial-projects-design.md` (§4 architecture, §6 quality bar, §7 project 1) and `docs/pipeline-design-principles.md`. Executors read both.

## Review Focus

1. **Supabase not configured or unreachable** (placeholders unset, network down, 5xx): the leaderboard still renders; vote buttons show disabled or "couldn't save, try again" rather than spinning forever or throwing. Test: Task 4 `vote client: unreachable server returns {ok:false}` and Task 6 `smoke: page works with no Supabase env`.
2. **Repeat vote from the same browser** (button double-tap, a second tab): the second insert hits the unique constraint (HTTP 409) and the UI treats it as "already voted", not an error. Test: Task 4 `vote client: 409 counts as already voted`.
3. **localStorage unavailable** (Safari private mode, blocked storage): voting still works for the session (in-memory voter id) and nothing throws. Test: Task 4 `voter id falls back when localStorage throws`.
4. **Park name collisions and odd names** (two parks with the same name, macrons like "Ōtākaro", apostrophes, slashes): slugs are unique, URL-safe and stable between runs. Test: Task 1 `test_slugify_unique_handles_collisions_and_macrons`.
5. **All weights set to zero in the personal ranking**: there's no NaN or divide-by-zero; the list falls back to the default order and says "pick at least one thing you care about". Test: Task 3 `scoring: all-zero weights fall back to default`.

### Task 1: Park scoring functions

**Files:** Create `projects/__init__.py`, `projects/best_park/__init__.py`, `projects/best_park/layers.toml`, `projects/best_park/score.py`, `tests/test_best_park.py`.

**Interfaces:**
- Consumes: nothing from `ccc_data` (pure functions over GeoDataFrames in EPSG:2193).
- Produces (in `projects/best_park/score.py`):
  - `INCLUDED_TYPES = {"Local/Community Park", "Sports Park", "Regional Park", "Garden & Heritage Park", "Residential Red Zone"}`. This excludes Utility Park (229), Cemetery (23) and Plant Nursery (1); counts are from 2026-11-01.
  - `MIN_AREA_HA = 0.1`, `BUFFER_M = 20.0`, `TREE_DENSITY_CAP = 200.0` (trees/ha)
  - `FACTORS: list[tuple[str, str]]`: `[("play","Playground equipment"), ("seating","Seats & picnic tables"), ("bbq","Barbecues"), ("water","Drinking water & showers"), ("sport","Sports fields"), ("dogs","Dog exercise area"), ("trees","Tree cover"), ("size","Size")]`
  - `WEIGHTS: dict[str, float] = {"play": 2, "seating": 1, "bbq": 1, "water": 1, "sport": 1, "dogs": 1, "trees": 1.5, "size": 1.5}`. These are tunable defaults, decided by Claude.
  - `select_parks(parks: GeoDataFrame, log: list[dict]) -> GeoDataFrame`: keeps rows with `Type ∈ INCLUDED_TYPES` and `drvArea/1e4 ≥ MIN_AREA_HA`, calling `log_step` once per filter
  - `raw_factors(parks: GeoDataFrame, layers: dict[str, GeoDataFrame]) -> DataFrame`, indexed by `ParkID`, with one column per factor key:
    - `play`: count of `play_equipment` points in the park buffered by `BUFFER_M`
    - `seating`: `seat + picnic_table` counts
    - `bbq`, `water` (`drinking_fountain + shower`) and `sport` (`sport_field` polygons intersecting): counts
    - `dogs`: 1.0 if any `dog_exercise_area` intersects, else 0.0
    - `trees`: `tree` count per ha, capped at `TREE_DENSITY_CAP`
    - `size`: area in ha
    - Uses `gpd.sjoin(..., predicate="intersects")` against buffered park polygons.
  - `percentiles(raw: DataFrame) -> DataFrame`: per column, `rank(pct=True, method="average")`, with an all-zero column mapping to 0.0
  - `score(pct: DataFrame, weights: dict[str, float]) -> Series`: `100 * Σ(w·p) / Σw`, rounded to 1 decimal. If `Σw == 0`, it uses `WEIGHTS`.
  - `slugify_unique(names: list[str]) -> list[str]`: NFKD with combining marks stripped (so "Ōtākaro" becomes "otakaro"), lowercase, any non-`[a-z0-9]` run becomes `-`, stripped of `-`; an empty result becomes `"park"`. Collisions get `-2`, `-3`, … in input order. Callers pass names sorted by `ParkID` so slugs are stable.
- `layers.toml` keys, each with `exclude = ["DonorName", "DonatedBy"]` where those fields exist:
  - `park` (GreenAsset/Park)
  - `play_equipment` (Furniture/Play Equipment)
  - `seat` (Furniture/Seat), `picnic_table` (Furniture/Picnic Table), `bbq` (Furniture/Barbecue), `shower` (Furniture/Shower)
  - `drinking_fountain` (WaterSupply/Drinking Fountain)
  - `sport_field` (Recreation/Sport Field), `dog_exercise_area` (Recreation/Dog Exercise Area)
  - `tree` (Tree/Tree)
  - `fetch` drops excluded fields only if the layer has them. Rule: list exactly the fields the layer has; `resolve(...).fields` tells you.

### Task 2: Best Park pipeline + committed outputs

**Files:** Create `projects/best_park/pipeline.py`, `tests/test_best_park_outputs.py`, and `projects/best_park/outputs/*` (generated).

**Interfaces:**
- Consumes: `ccc_data.load_layers, log_step, export_web, write_manifest`; everything in `score.py`.
- Produces:
  - `run(*, refresh: bool = False, root: Path = Path("projects")) -> Path`, which returns the outputs dir
  - `check(out_dir: Path = Path("projects/best_park/outputs")) -> None`, which raises `AssertionError` with a message
  - `projects/best_park/outputs/parks.json`, using this schema (the site depends on it):
    ```json
    {"schema_version": 1, "data_pulled_at": "<ISO>", "weights": {...WEIGHTS}, "factors": [{"key": "play", "label": "Playground equipment"}, ...],
     "parks": [{"id": "<ParkID>", "slug": "...", "name": "...", "type": "...", "area_ha": 1.23,
                "lon": 172.6, "lat": -43.5, "raw": {"play": 4, ...}, "pct": {"play": 0.93, ...}, "score": 81.2, "rank": 1}]}
    ```
    `parks` are sorted by `rank` (1 = best; ties broken by `area_ha` descending, then `name`). `lon`/`lat` come from `representative_point()` in 4326, rounded to 5 dp. Floats are rounded to 3 dp.

  - `metrics.json` = `{"n_parks": int, "top5": [names], "data_pulled_at": "<ISO>"}`
  - `manifest.json` via `write_manifest`
  - `__main__`: `python -m projects.best_park.pipeline [--refresh]` runs `run()` then `check()`, and prints `best_park: <n> parks, #1 <name> (<score>)`.

### Task 4: Supabase votes + feedback (with placeholders)

**Files:** Create `supabase/migrations/001_votes_feedback.sql`, `site/src/lib/votes.ts`, `site/src/components/VoteButton.astro`, `site/src/components/Feedback.astro`, `site/tests/votes.test.ts`, `SETUP.md`. Modify `site/src/pages/parks/index.astro` (add the People's Choice tab and Data vs People section).

**Interfaces:**
- SQL (exact objects):
  - `park_votes(park_id text not null, voter_id uuid not null, ip_hash text, created_at timestamptz default now(), primary key (park_id, voter_id))`
  - `feedback(project text not null, item_id text, value smallint check (value in (-1, 1)), voter_id uuid, created_at timestamptz default now())`
  - view `park_vote_counts(park_id, votes)`
  - RLS is on for both tables. Policies grant `anon` insert only, with no select, update or delete on the tables; `grant select on park_vote_counts to anon`.
  - Trigger `limit_votes`: it sets `ip_hash = encode(digest(split_part(current_setting('request.headers', true)::json->>'x-forwarded-for', ',', 1), 'sha256'), 'hex')`, and raises if the same `ip_hash` inserted more than 30 votes in the last 10 minutes (via `pgcrypto`). This is a deliberate limited defence: it can't stop a determined cheater (design §7.1).
- `votes.ts`:
  - `getVoterId(storage?: Storage): string` returns a UUID; it persists under the key `cp_voter_id` and falls back to an in-memory value when storage throws.
  - `votingEnabled(): boolean` is true only when both Supabase env vars are set.
  - `castVote(parkId: string, f?: typeof fetch): Promise<{ok: boolean; already?: boolean; error?: string}>`. It POSTs `${URL}/rest/v1/park_votes` with headers `apikey`, `Authorization: Bearer <anon>` and `Prefer: return=minimal`. A 201 gives `{ok:true}`; a 409 gives `{ok:true, already:true}`; anything else or a network error gives `{ok:false, error}`, with a 5 s timeout via `AbortController`.
  - `getCounts(f?): Promise<Record<string, number> | null>` GETs `park_vote_counts?select=park_id,votes` and returns `null` on any failure.
  - `sendFeedback(project, itemId, value: 1 | -1, f?)` follows the same pattern against `feedback`.
  - Voted park ids are remembered in localStorage `cp_voted` (an array).
- Page behaviour:
  - The People's Choice tab ranks parks by votes.
  - Data vs People lists the 5 parks with the largest positive rank gap ("underrated by the data") and the 5 with the largest negative gap. It's hidden until there are ≥ 20 total votes, and shows "Not enough votes yet: be one of the first" until then.
  - `VoteButton` states are: idle, saving, voted ✓, "already voted", "couldn't save, try again", and disabled with "Voting coming soon" when `!votingEnabled()`.
  - `Feedback` shows 👍/👎 under the results ("Was this ranking useful?") plus a form link.
